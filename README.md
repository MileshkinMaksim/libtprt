# TPRT — C++ библиотека двухточечного сейсмического лучевого трассирования

## 1. Общее описание

`libtprt` (Two-Point Ray Tracing) — C++ библиотека для расчета кинематических характеристик и пространственных траекторий сейсмических лучей в трехмерных слоисто-анизотропных VTI (Transversely Isotropic with Vertical Axis of Symmetry) и изотропных средах. 

Расчет траекторий выполняется между фиксированными 3D-координатами источника и приемника путем отыскания узлов преломления, минимизирующих полное время пробега волны в соответствии с принципом Ферма (двухточечный метод изгиба луча / Two-Point Bending Method).

## 2. Архитектура библиотеки

Библиотека разработана в соответствии с модульным принципом. Исходный код распределен по следующим подсистемам:

```text
include/tprt/
├── Core/
│   ├── Types.hpp            # Базовые типы данных, перечисления мод волн и структур
│   └── ElasticTensor.hpp    # Преобразования параметров Томсена и матрицы Войгта в тензор жесткости
├── Geometry/
│   ├── Horizon.hpp          # Абстрактный интерфейс сейсмической границы z(x,y)
│   ├── FlatHorizon.hpp      # Наклонная или горизонтальная плоская граница
│   └── GridHorizon.hpp      # Криволинейная граница на регулярной 2D-сетке узлов
├── Kinematics/
│   ├── Christoffel.hpp      # Солвер уравнения Кристоффеля (фазовые/групповые скорости, поляризация)
│   └── VTISlownessSpline.hpp# Сплайн-аппроксимация лучевой медленности VTI-среды
├── Model/
│   ├── Layer.hpp            # Класс однородного сейсмического слоя
│   └── VelocityModel.hpp    # Вертикальный стек слоев скоростной модели
├── Ray/
│   ├── RayCode.hpp          # Код луча (последовательность проходимых слоев и типов волн)
│   ├── RayTrajectory.hpp    # Траектория луча и промежуточные узлы
│   └── Ray.hpp              # Высокоуровневое представление лучевой задачи
├── Solver/
│   └── TwoPointBendingTracer.hpp # Минимизатор времени пробега на базе метода L-BFGS
└── IO/
    └── JsonParser.hpp       # Загрузка скоростных моделей и геометрических конфигураций из JSON
```

### Основные модули и классы

1. **Модуль тензорных преобразований (`Core`)**:
   - `Types.hpp`: описывает основные математические векторы Eigen (`Point3D`, `Vector3D`), перечисления типов волн (`WaveType::qP = 0`, `WaveType::qS1 = 1`, `WaveType::qS2 = 2`), типов сред (`MediumType::ISOTROPIC`, `MediumType::VTI`), 4D тензор плотности упругих модулей `Tensor4D` ($A_{ijkl}$) и параметры Томсена (`ThomsenParams`).
   - `ElasticTensor`: пересчитывает изотропные параметры $(v_p, v_s, \rho)$ или параметры Томсена $(v_{p0}, v_{s0}, \epsilon, \delta, \gamma, \rho)$ в 6x6 матрицу Войгта $C_{ij}$, после чего формирует 4D тензор жесткости $A_{ijkl} = \frac{C_{ijkl}}{\rho}$.

2. **Модуль анизотропной кинематики (`Kinematics`)**:
   - `ChristoffelSolver`: выполняет решение акустического тензорного уравнения Кристоффеля $(\Gamma_{ik} - v^2 \delta_{ik}) p_k = 0$, где $\Gamma_{ik} = A_{ijkl} n_j n_l$. Определяет фазовую скорость $v$, вектор поляризации $\mathbf{p}$ и вектор групповой скорости $\mathbf{v}_g$ для мод $qP$, $qS1$ ($qSV$) и $qS2$ ($qSH$).
   - `VTISlownessSpline`: строит 1D кубический сплайн зависимости лучевой медленности $S_g(\theta_g) = \frac{1}{|\mathbf{v}_g|}$ от лучевого угла $\theta_g \in [0, \pi/2]$. Позволяет вычислять время пробега волны на отрезке $t = S_g(\theta_g) \cdot L$ за время $O(1)$.

3. **Модуль геометрии границ (`Geometry`)**:
   - `Horizon`: абстрактный базовый класс геометрии раздела слоев с методами получения глубины $z(x, y)$ и вектора внешней нормали $\mathbf{n}(x, y)$.
   - `FlatHorizon`: аналитическая плоская граница, задаваемая глубиной $z_0$, углом падения и азимутом.
   - `GridHorizon`: криволинейная граница, заданная сеточной поверхностью $z(x_i, y_j)$, с интерполяцией методом бикубического сплайна (`_2D::BicubicInterpolator`).

4. **Модуль скоростной среды (`Model`)**:
   - `Layer`: описывает свойства слоя. Хранит ссылку на верхнюю границу `Horizon`, упругие параметры и предварительно построенные сплайны медленности `VTISlownessSpline` для всех мод волн.
   - `VelocityModel`: представляет вертикальный стек слоев и определяет индекс слоя для любой 3D-точки пространства.

5. **Модуль лучевого трассирования (`Ray`, `Solver`)**:
   - `RayCode`: хранит последовательность сегментов луча, содержащую индекс слоя и тип волны для каждого отрезка пути.
   - `TwoPointBendingTracer`: численный решатель задачи изгиба. Выполняет минимизацию целевой функции полного времени пробега волны относительно горизонтальных координат $(x_k, y_k)$ промежуточных узлов преломления на границах слоев. Оптимизация осуществляется алгоритмом L-BFGS из библиотеки NLopt.

6. **Модуль ввода-вывода (`IO`)**:
   - `JsonParser`: считывает конфигурационные файлы JSON с описанием слоистых моделей, расстановкой приемников и эталонными временами пробега с использованием библиотеки RapidJSON.

## 3. Требования к окружению и зависимости

Для сборки и использования библиотеки требуются следующие компоненты:

- Компилятор C++ с поддержкой стандарта C++17 (GCC $\ge$ 8, Clang $\ge$ 7, MSVC 2019+).
- Система сборки `CMake` версии 3.18 или выше.
- `Eigen3` ($\ge$ 3.3) — библиотека линейной алгебры.
- `NLopt` — библиотека численной нелинейной оптимизации.
- `libInterpolate` — библиотека сплайн-интерполяции (загружается автоматически через CMake / FetchContent при отсутствии в системе).
- `RapidJSON` — библиотека разбора файлов формата JSON.
- `GoogleTest (GTest)` — фреймворк для запуска модульных и интеграционных автотестов.

### Установка зависимостей в Ubuntu / Debian / WSL:

```bash
sudo apt update
sudo apt install -y build-essential cmake libeigen3-dev libnlopt-dev rapidjson-dev libgtest-dev libboost-dev
```

## 4. Сборка проекта

Сборка осуществляется стандартными средствами CMake.

```bash
# 1. Переход в корневую директорию проекта
cd libtprt

# 2. Создание и переход в директорию сборки
mkdir -p build && cd build

# 3. Конфигурация CMake в режиме оптимизации Release
cmake -DCMAKE_BUILD_TYPE=Release ..

# 4. Компиляция библиотеки и автотестов
cmake --build . --config Release --parallel
```

После завершения компиляции в директории `build/` формируются:
- Статическая библиотека `libtprt.a` (или `tprt.lib` на платформах Windows).
- Исполняемый файл юнит-тестов `tprt_autotests`.

## 5. Запуск автотестов и верификация точности

Библиотека содержит встроенный набор автотестов, проверяющих сортировку мод Кристоффеля, аналитические решения в однородных средах, а также точность трассирования на 5 эталонных геологических моделях из директории `Autotest_Data`.

Для выполнения всех тестов запустите скопилированный бинарник:

```bash
# Перенос или проверка наличия директории с тестовыми данными
cp -r ../Autotest_Data . 2>/dev/null || true

# Запуск автотестов
./tprt_autotests
```

Альтернативный запуск через CTest:

```bash
ctest --output-on-failure
```

При прогоне на эталонных наборах данных в консоль выводится статистика погрешностей:
- **MAE** (Mean Absolute Error) — средняя абсолютная ошибка времен пробега (в микросекундах).
- **RMSE** (Root Mean Square Error) — среднеквадратичная ошибка (в микросекундах).
- **MaxAE** (Maximum Absolute Error) — максимальная абсолютная ошибка (в микросекундах).
- **MRE** (Mean Relative Error) — средняя относительная ошибка (в процентах).

## 6. Руководство по использованию API библиотеки

Ниже приведен полный пример программы на C++, демонстирующий создание двухслойной VTI-модели, формирование кода преломленного луча и выполнение трассирования между источником и приемником.

```cpp
#include <iostream>
#include <memory>
#include "tprt/Core/Types.hpp"
#include "tprt/Geometry/FlatHorizon.hpp"
#include "tprt/Model/VelocityModel.hpp"
#include "tprt/Solver/TwoPointBendingTracer.hpp"

using namespace tprt;

int main() {
    // 1. Задание параметров анизотропии Томсена для верхнего слоя
    ThomsenParams top_layer_params;
    top_layer_params.vp0 = 2000.0;   // Вертикальная скорость P-волны (м/с)
    top_layer_params.vs0 = 1000.0;   // Вертикальная скорость S-волны (м/с)
    top_layer_params.epsilon = 0.1;  // Параметр Томсена epsilon
    top_layer_params.delta = 0.2;    // Параметр Томсена delta
    top_layer_params.gamma = 0.0;    // Параметр Томсена gamma
    top_layer_params.rho = 2000.0;   // Плотность среды (кг/м^3)

    // 2. Задание параметров для нижнего слоя
    ThomsenParams bot_layer_params;
    bot_layer_params.vp0 = 3000.0;
    bot_layer_params.vs0 = 1500.0;
    bot_layer_params.epsilon = 0.2;
    bot_layer_params.delta = 0.1;
    bot_layer_params.gamma = 0.1;
    bot_layer_params.rho = 2400.0;

    // 3. Формирование скоростной модели
    VelocityModel model;

    // Слой 1: дневная поверхность z = 0 м
    auto horizon_0 = std::make_shared<FlatHorizon>(0.0);
    model.addLayer(Layer(horizon_0, MediumType::VTI, top_layer_params));

    // Слой 2: плоская граница раздела на глубине z = 500 м
    auto horizon_1 = std::make_shared<FlatHorizon>(500.0);
    model.addLayer(Layer(horizon_1, MediumType::VTI, bot_layer_params));

    // 4. Определение точек источника и приемника
    Point3D source(0.0, 0.0, 0.0);
    Point3D receiver(1200.0, 0.0, 800.0);

    // 5. Построение кода луча (продольная волна qP в 1-м и 2-м слоях)
    RayCode code;
    code.addSegment(0, WaveType::qP);
    code.addSegment(1, WaveType::qP);

    // 6. Инициализация и запуск решателя задачи изгиба
    TwoPointBendingTracer tracer(model);
    RayTrajectory trajectory = tracer.solve(source, receiver, code);

    // 7. Обработка полученных результатов
    if (trajectory.converged) {
        std::cout << "Трассирование завершено успешно." << std::endl;
        std::cout << "Полное время пробега: " << trajectory.total_travel_time * 1000.0 << " мс" << std::endl;
        std::cout << "Координаты узлов траектории:" << std::endl;
        for (size_t i = 0; i < trajectory.points.size(); ++i) {
            const auto& p = trajectory.points[i];
            std::cout << "  Узел " << i << ": X = " << p.x() 
                      << " м, Y = " << p.y() 
                      << " м, Z = " << p.z() << " м" << std::endl;
        }
    } else {
        std::cerr << "Ошибка: алгоритм оптимизации траектории не сошелся." << std::endl;
    }

    return 0;
}
```

## 7. Спецификация конфигурационных JSON-файлов

### 7.1. Файл геолого-геофизической модели (`model_config_test_X.json`)

Файл содержит массив слоев `layers`. Граница `z_top` определяет верхнюю кровлю слоя.

```json
{
  "layers": [
    {
      "z_top": 0.0,
      "rho": 2000.0,
      "thomsen_parameters": {
        "vp0": 2000.0,
        "vs0": 1000.0,
        "epsilon": 0.1,
        "delta": 0.2,
        "gamma": 0.0
      }
    },
    {
      "z_top": 500.0,
      "rho": 2400.0,
      "thomsen_parameters": {
        "vp0": 3000.0,
        "vs0": 1500.0,
        "epsilon": 0.2,
        "delta": 0.1,
        "gamma": 0.1
      }
    }
  ]
}
```

### 7.2. Файл расстановки приемников (`receivers.json`)

Определяет список точек наблюдения и их 3D-координаты.

```json

  {
    "receiver_number": 1,

    }
  },
  {
    "receiver_number": 2,

    }

]
```
